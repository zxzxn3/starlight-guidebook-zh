Secure Terminal

Main Communications ConsoleComputerComms

Keycard Authentication DeviceKeycardAuth

The Secure Terminal is a system built into the station's Main Communications Console. It gives command staff a formal way to request and authorise major decisions; things like calling Emergency Response Teams, escalating the station's alert level, or deploying emergency armories.

Every request made through this system is announced to the station, and in most cases requires multiple people to co-authorize before anything happens.

Starting a Request

Only someone who holds the correct access can open a proposal. There are typically two Main Communications Consoles on the station where requests can be started; one on the Bridge and one in the Captain's office. Either works.

In the Main Communications Console, select 'Secure Terminal' to begin. From there you will see a list of available requests. Select the one relevant to the situation, provide a reason if prompted, and submit it. The terminal will immediately notify all Keycard Authentication Devices on the station that a proposal is pending.

Keep in mind:

  • Only one proposal can be active at a time.
  • Most requests have a fee drawn from your account when submitted; this is held until the proposal resolves.
  • Certain requests are one-time-use per shift and cannot be re-submitted once used.
  • You and all co-authorizers must stay and keep your terminal windows open until all required co-authorizations are gathered. Closing the window cancels the request (for the requester) or revokes your authorization.

Co-Authorization

Most requests require more than one person to approve them before anything happens. This is where the Keycard Authentication Devices come in.

The Captain and every head of staff has one of these devices installed in their office. When a proposal is active, the authentication device will light up blue. A co-authorizer can walk up to it, and add their authorization to the pending request.

All Keycard Authentication Devices on the station are identical; they are not tied to a specific head of staff. Any command member with the right access can walk up to any device, regardless of whose office it is in, and use it to co-authorize a pending proposal.

Each Main Communications Console and each Keycard Authentication Device can only contribute one authorization per request. Once a device has been used to authorise a proposal, it is locked out for that request; a second person cannot use the same device to co-authorize and will need to find a different Keycard Authentication Device or Main Communications Console.

Additionally, each individual command member can only authorize once per request.

There is no time limit for gathering co-authorizations. However, active presence is strictly required: the requester and all co-authorizers must keep their terminal windows open until all authorizations are gathered.

  • If the requester closes their window, the pending proposal is immediately cancelled and any held fee is refunded.
  • If a co-authorizer closes their window before all authorizations are collected, their authorization is revoked. If all authorizations are lost, the proposal cancels.

Once all required co-authorizations are collected, the requester and authorizers can safely close their terminal windows. The proposal will then begin its countdown (or await Central Command approval if required), activating automatically when the timer runs out.

A Few Things Worth Knowing

  • Canceling a proposal: While any proposal is still gathering authorizations (pending), any Command member can cancel it from a console. Once all authorizations are gathered and the activation countdown begins, non-ERT requests cannot be cancelled.
  • Rescinding an ERT dispatch: Emergency Response Teams have an en-route transit countdown (5 to 30 minutes). During this arrival countdown, Command can rescind the dispatch from a console if the threat is neutralized or contained before the team arrives. Rescinding requires satisfying that team's specific rescind scheme (such as designated Heads of Staff or multiple Command members). Those voting to rescind must also keep their terminal windows open until the threshold is satisfied.
  • Some requests require Central Command approval before they activate, regardless of how many command staff have authorized. If no Central Command members are available, certain requests will bypass this and proceed automatically.
  • Armories and pods can be recalled if they block evac or are no longer needed, once a short cooldown has elapsed.
  • If both consoles are destroyed or otherwise unavailable, the Captain's locker contains a Communications Computer Board that can be used to build a replacement.
  • If the terminal cannot be used at all, a fax to Central Command is the next best option. As a last resort, the red phone in the Captain's office provides a direct line, though this should only be used if nothing else is available.
